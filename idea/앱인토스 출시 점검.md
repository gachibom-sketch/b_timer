- 점검한 날: 2026-10-29

## 한 줄 결론

지금의 Streamlit(파이썬으로 웹 화면을 만드는 도구) 앱은 그대로 올릴 수 없다.
- 까닭: 토스는 토스 밖 주소의 화면을 띄우는 것과 서버가 화면을 그리는 방식을 막는다.
- 해야 할 일: 화면을 웹 코드로 다시 만들어 앱 묶음(번들)으로 올려야 한다.
- 그 밖에 큰 것 세 가지: 라이트 모드(밝은 화면), 구글 로그인 불가, 휴대폰 화면
- 1라운드(11/5까지)는 그대로 가도 된다.

## 만드는 방식 비교

| 방식 | 되나 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| A. 지금 Streamlit 주소를 토스 앱 안에서 열기 | 안 됨 | — | 토스 밖 주소의 화면, iframe, 서버가 그리는 화면이 모두 금지 [비게임] · [시작하기] |
| B. WebView SDK + 웹 화면 새로 만들기 + Supabase 를 브라우저에서 바로 쓰기 | 됨 | 공식 안내가 이 길이다("기존 웹 프로젝트에 SDK 연동하기") [웹뷰 안내]. Supabase 연동 공식 안내가 있다 [Supabase]. 별도 서버 없이 된다 [FAQ]. 식별키를 쓰면 사업자가 필요 없다 [사업자] | 화면과 계산을 자바스크립트로 다시 써야 한다 |
| C. React Native SDK(휴대폰 앱처럼 만드는 개발 도구) | 됨 | 앱에 가까운 성능 [시작하기] | 이 앱에는 과하고, 새로 배울 것이 많다 |

**권함: B.**
- 공식 문서가 기존 웹 서비스를 옮기는 길로 안내한다.
- 지금 쓰는 Supabase 표를 그대로 이어 쓸 수 있다.
- 사업자 등록 없이 낼 수 있다.
- 화면은 React(화면 만드는 자바스크립트 도구)와 Vite(웹 코드를 묶는 도구)로 만든다. 공식 안내 예제가 이 조합이다 [웹뷰 안내] · [Supabase].
- (판단) B로 만든 웹 코드는 일반 브라우저에서도 열린다. 하지만 사용자 식별키는 토스 앱 안에서만 나와서 브라우저에서는 사람을 구분할 수 없다. 그래서 한 벌로 합친 뒤에는 토스 밖 웹 주소를 닫는 것이 자연스럽다.

## 1라운드(11/5까지)에 미치는 영향

**1라운드는 그대로.** 토스 조건은 모두 토스판에만 걸리고, PC 브라우저용 1라운드 웹판에는 걸리지 않는다.

아래는 참고이고, 하지 않아도 된다.
- **사용자 칸 이름**: 11/3 구글 로그인 때 Supabase 의 사용자 칸 이름을 "계정 번호"처럼 구글에 묶이지 않게 둔다. 그러면 토스판에서 식별키를 같은 칸에 넣을 수 있다. PRD 도 이미 "계정 번호"라고 쓴다.
- **계산 함수 떼어 두기**: 주말 별자리 작업 때 달성률·기간·덤 별 계산을 화면 코드와 떼어 작은 함수로 둔다. 그러면 나중에 자바스크립트로 옮기기 쉽다.

PRD.md 에 바꿀 문구 제안 — 1라운드 내용은 그대로 두고, 비목표 68줄 "네이티브 앱" 아래에 한 줄만 더한다. 아래 결정을 반영한 문구다.

```
- 토스 앱 미니앱(앱인토스) 출시 — 까닭: 1라운드는 PC 웹으로 만든다. 앱인토스는 휴대폰 토스 앱 안에서만 열리고, 라이트 모드만·토스 로그인만 허용하며 서버가 그리는 화면(Streamlit)을 막아서 화면을 웹 코드로 다시 만들어야 한다. 교육이 끝나고 휴대폰 확인·MP4 영상 저장 다음에 하며, 그때 웹판과 구글 로그인은 없애고 토스판 코드 한 벌로 합치고 사용자는 토스 사용자 식별키로 구분한다. (2026-10-29 결정, 점검: idea/앱인토스 출시 점검.md)
```

## 결정 (2026-10-29)

1. **토스판 사용자 구분**: 사용자 식별키. 사업자 등록, 로그인 화면, 자체 서버 없이 간다.
2. **시작 시점**: 교육(11/5)이 끝난 뒤, 이미 정한 "휴대폰 확인 → MP4(영상 파일) 저장" 다음
   - 참고: 휴대폰 확인과 MP4 를 Streamlit 웹판에서 먼저 하면, 토스판으로 합칠 때 MP4 를 다시 만들어야 한다.
3. **코드**: 교육이 끝나면 토스판 코드 한 벌로 합친다.
4. **디자인**: 바탕은 밝게, 밤하늘 칸만 어둡게. 시안은 [토스판 시안](screens/토스판/README.md)에 있다.
5. **카드 하단 배포 주소**: 제안 1대로 한다. 토스판 카드에서 주소를 빼고 "토스에서 ‘별모도로’ 검색"을 글자로 넣는다.
6. **웹판 기록**: 구글 로그인은 교육 때문에 넣은 것이라 교육 뒤 없앤다. 제안 2대로 잇지 않고 정리한다.

## 제안 1 — 토스판 카드의 배포 주소 (2026-10-29 이대로 결정)

**권함: 주소를 빼고, 그 자리에 "토스에서 ‘별모도로’ 검색"을 글자로만 넣는다.** 붙는 화면: 화면 3 (카드 미리보기)

- 교육 뒤 한 벌로 합치면 Streamlit 웹 주소는 닫힌다. 그래서 주소를 남기면 카드에 죽은 주소가 남는다.
- 토스 밖 사이트로 이끄는 것은 제한된다 [오픈 정책] 2-2. 카드 그림 속 글자가 여기에 해당하는지는 **확인 못 함**. 토스 안 검색으로 이끌면 이 걱정이 없다.
- 카드를 SNS 에서 본 사람이 자기 휴대폰에서 바로 따라 할 수 있다.
- 토스 로고는 보도자료 가이드대로만 쓸 수 있어서 [FAQ], 로고 없이 글자만 쓴다.

다른 안

| 안 | 아쉬운 점 |
|---|---|
| 아무것도 넣지 않기 | 가장 안전하지만, 카드를 본 사람이 찾아올 길이 없다 |
| 토스 공유 링크(Share.createLink — 토스 앱에서 미니앱을 여는 링크)를 QR 코드로 넣기 | SNS 를 휴대폰으로 보는 사람은 자기 화면의 QR 을 찍을 수 없고, 카드가 복잡해진다. 공유 링크는 나중에 "링크 공유" 단추로 따로 검토한다 (PRD 비목표 "SNS 직접 올리기 연동"과 함께) |

## 제안 2 — 웹판 기록(구글 계정) 정리 (2026-10-29 이대로 결정)

**권함: 잇지 않고 정리한다.** 붙는 화면: 화면 아님 (Supabase 정리)

1. **결과 남기기**: 11/5 교육이 끝나면 PRD 판정 지표 숫자를 Supabase 에서 뽑아 idea/ 에 결과 문서로 남긴다.
2. **백업과 삭제**: 웹판 기록(progress·목표 표·event_log 의 구글 계정 줄)은 이 컴퓨터에 CSV(표 파일)로 받아 둔다. 공개 저장소 밖에 두고 올리지 않는다. 그다음 Supabase 에서 지운다.
3. **설정 지우기**: 구글 로그인 설정(구글 클라우드의 로그인 설정·시험 사용자)과 배포 설정의 비밀 값도 지운다.
4. **토스판 시작**: 같은 표 구조를 다시 쓰되 빈 표에서 시작한다. "계정 번호" 칸에는 식별키를 넣는다.

때
- 1은 11/5 교육이 끝난 직후에 한다.
- 2~4는 토스판으로 합칠 때(웹판을 닫을 때) 한다. 그 사이 휴대폰 확인과 MP4 작업에는 웹판과 구글 로그인이 그대로 돌아야 하기 때문이다.

까닭
- 웹판을 쓴 사람은 조원 몇 명뿐이라 이을 가치가 작다.
- 구글 계정 정보를 남기지 않는다.
- 잇는 장치를 만들 일이 없다.

다른 안 — 이어 주기 (권하지 않음)
- 웹판에서 한 번만 쓰는 숫자 코드를 받아 토스판 화면 2 (밤하늘)의 "웹 기록 가져오기"에 넣으면, 서버가 구글 계정 줄을 식별키 줄로 옮긴다.
- 코드 화면·서버 함수·코드 만료 처리가 필요하고(중간 크기), 쓸 사람이 거의 없다.

1라운드 쪽 준비 (하지 않아도 됨)
- 11/3 구글 로그인을 만들 때 로그인 부분을 한 파일에 모아 둔다. 그러면 교육 뒤 떼어 내기 쉽다.
